## Current routing after this change

1. Exact quick replies, crisis handling, known commands, app tools and medicine lookup run without an LLM.
2. A sufficiently grounded local RAG answer may answer a precision query directly.
3. Otherwise, an installed local model gets the request first. For precision questions its system instruction requires an explicit uncertainty response when retrieved evidence is inadequate.
4. Cloud is eligible only for a signed-in, consented, non-safety turn after local generation is unavailable, fails, or explicitly declines for insufficient evidence. Guest turns remain local.
5. If cloud is unavailable, the deterministic local coach remains the final fallback.

The current escalation gate is a refusal/failure signal, not a calibrated quality estimator. No measured per-category success rates, provider cost model or held-out routing evaluation was found. Do not claim the expected utility or latency model is calibrated until those data exist.

## Known disconnected or incomplete paths

- `StatefulOrchestrator` has real functionality but is development-only; production agent does not call it.
- `LocalAI.generateStructured` is available natively but no production assistant caller was found in this search.
- `thriveRag.syncFts()` is a diagnostics/rebuild entry point; normal writes update FTS through existing store methods.
- Cloud answer learning is intentionally disabled until RAG supports explicit review/provenance status. The old automatic write assigned every generated answer a fabricated `0.90` confidence. Conversation turns are indexed separately as context and excluded from grounded answer results; only explicit conversation-recall queries include them in model context.
- Retrieval confidence weights and the `0.70` answer threshold have not been shown to be calibrated against held-out labeled queries.
- No physical-device inference, offline, voice/action regression, thermal, memory, or cloud escalation verification was performed during this source audit.
